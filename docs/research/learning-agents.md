# Learning agents for FirstPlay Autofill — research notes

Date: 2026-10-01. Web sources only; unverifiable numbers are omitted and flagged. Nothing written to a repo.

## 1. Memory and self-improvement in language agents

| Paper | Mechanism | Reported effect | Implies for FirstPlay |
|---|---|---|---|
| [CoALA, Sumers 2023](https://arxiv.org/abs/2309.02427) | Working / episodic / semantic / procedural memory; internal actions = reasoning, retrieval, *learning* (writes). "Updates to procedural memory are risky." | Framework, no benchmark | Write episodic and semantic memory only; never let the agent rewrite its own fill procedures. |
| [Reflexion, Shinn 2023](https://arxiv.org/abs/2303.11366) | After failure, model writes a verbal reflection into an episodic buffer truncated to the last 1-3 | AlfWorld 130/134 (+22 pts over ReAct); HotPotQA +20 pts; HumanEval 91% pass@1 | Needs a trustworthy failure signal; FirstPlay has one (the user's edit). A bounded lesson buffer per ATS is cheap. |
| [Voyager, Wang 2023](https://arxiv.org/abs/2305.16291) | Skill library of *verified executable code*, embedding-retrieved; iterative prompting on env feedback | 3.3x unique items, 15.3x faster tech tree, 2.3x distance | Your "skills" are per-widget fill procedures; keep them hand-written and tested, not model-generated. |
| [Generative Agents, Park 2023](https://arxiv.org/abs/2304.03442) | Memory stream; retrieval scored by recency x importance x relevance; periodic reflection into higher-level insights | Ablation: observation, planning, reflection each needed | Recency-weighted retrieval fits "what did I answer last time"; reflection *is* generalisation and must be shown to the user. |
| [MemGPT / Letta, 2023](https://arxiv.org/abs/2310.08560) | LLM edits its own memory tiers (core vs archival) via function calls | Qualitative: long-doc QA, consistent multi-session chat | Fine in the backend, but keep memory typed (fact, provenance, timestamp, confidence), never free text. |
| [Agent Workflow Memory, Wang 2024](https://arxiv.org/abs/2409.07429) | Induce reusable workflows from past trajectories (offline or online), inject as guidance | Mind2Web +24.6% rel., WebArena +51.1% rel., fewer steps; +8.9-14.0 abs pts as train/test gap widens | Induce workflows offline from the frozen corpus and ship as code; online induction is the risky half. |
| [Synapse, Zheng 2023](https://arxiv.org/abs/2306.07863) | Trajectory-as-exemplar memory, state abstraction, embedding retrieval | MiniWoB++ 99.2%; Mind2Web +56% rel. step success | The user's own prior trajectory on the same form family is the exemplar: the replay primitive. |
| [ILF, Scheurer 2023](https://arxiv.org/abs/2303.16755) | Refine output from language feedback, pick best refinement, fine-tune on it | Scales with data; with comparison feedback reaches human-level summarisation | Don't fine-tune on correction text; use corrections as Jev labels and replayable values. |
| [ReasoningBank, 2025 (ICLR 2026)](https://arxiv.org/html/2509.25140) | Distil title/description/content "strategies" from *self-judged* successes and failures; LLM judge without ground truth | WebArena 40.5 -> 48.8 (Gemini-2.5-flash), +4.7 over AWM; up to 1.4x fewer steps; SWE-Bench-V +4.6 pts | Self-judging is the weak link; FirstPlay has a real judge (the user's final values), so skip LLM-as-judge. |
| [WebCoach, 2025](https://arxiv.org/abs/2511.12997) | Cross-session episodic store + "coach" that decides whether to inject *advice* | WebVoyager 47% -> 61% with a 38B model | A coach that injects advice, never actions, matches the never-submit stance. |
| [Budget-matched study, 2026](https://arxiv.org/abs/2606.15017) | AWM / ASI / ReasoningBank vs vanilla at equal token budget, 4 WebArena domains, 3 models | Vanilla "matches or surpasses all three"; run variance material | Published memory gains are partly token spend; measure by questions-asked-twice, not agent benchmarks. |
| Surveys: [Agent memory "second half"](https://arxiv.org/abs/2602.06052), [SSGM](https://arxiv.org/abs/2603.11768) | SSGM names semantic drift, leakage, error accumulation; proposes consistency checks, temporal decay, access control, decoupling memory evolution from execution | - | Memory writes must be user-confirmed, time-stamped, decayed, and kept off the fill path. |

**Transfers:** episodic replay, recency-weighted retrieval, bounded lesson buffers, offline workflow induction, typed memory with provenance and decay, advice-only coaching.
**Does not transfer:** model-generated skills, LLM-as-judge success labels, fine-tuning on feedback text, and any mechanism whose output is composed text, because the applicant certifies the document is "true, accurate and complete" under their own name ([Workday applicant terms](https://www.workday.com/en-ca/company/careers/terms-conditions.html)).

## 2. Learning from user corrections in form filling

- **Chromium Autofill** is the reference design: regex heuristics, then crowdsourced *votes*, then the `autocomplete` attribute. A vote is the field type implied by what the user actually submitted, keyed by `FormSignature` (hash of URL + field names) and `FieldSignature`; votes are overwritten when the user edits before submit, and uploads are throttled per (form x source). [README](https://chromium.googlesource.com/chromium/src/+/main/components/autofill/README.md). *Implies:* correction = per-field diff of filled vs submitted, keyed by form/field signature, throttled before trusted.
- **Prior art:** [US 11080597](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11080597) learns field-to-profile mapping from corrections; [field-label prediction](https://www.academia.edu/64708323/Field_Label_Prediction_for_Autofill_in_Web_Browsers) hit ~95% precision from ~4,000 labels. *Implies:* mapping accuracy plateaus; the remaining value is answer-level memory.
- **Stable vs company-specific:** no published rule found. Industry practice is exact-match reuse: Simplify reuses a saved answer only "when the exact same question appears again" ([help doc](https://help.simplify.jobs/articles/2415391-using-copilot-to-autofill-applications)). *Implies:* key replay on ATS + normalised question text + option set; promote to a profile fact only after the same value recurs across >= 2 distinct orgs *and* the user confirms. Exclude per-application fields (salary, start date, "how did you hear") from promotion by schema.
- **Noise:** Bitwarden's "Update existing login?" bar is the propose-don't-apply pattern; even so, release 2025.11 overwrote correct passwords on accept and OTP fields cause false prompts ([issue 20270](https://github.com/bitwarden/clients/issues/20270), [forum thread](https://community.bitwarden.com/t/frequent-notices-to-update-existing-login-save-new-login-with-latest-browser-extensions/90940)). *Implies:* ephemeral fields never trigger proposals; accepted updates need undo.
- **Propose vs auto-apply:** Horvitz's mixed-initiative principles: act only when expected utility beats asking, weigh the cost of a wrong guess ([CHI 1999](https://dl.acm.org/doi/10.1145/302979.303030)). An 18-clinician study found fully pre-populated suggestions produced "less agency: accepting improper mentions, and taking less initiative" ([arXiv 2103.04725](https://arxiv.org/abs/2103.04725)). In Semantic Commit (12 participants), half preferred to flag conflicts and resolve them locally rather than let the AI revise memory ([arXiv 2504.09283](https://arxiv.org/abs/2504.09283)). *Implies:* pre-fill high-confidence replays, but present memory changes as a diff to accept. I found **no** published acceptance rates for proposed vs auto-applied corrections in form filling; measure it yourself.

**Distinct and trustworthy.** Every complaint above is one of four: wrong values, fabricated content, unreviewed submissions, billing. FirstPlay negates the first three by construction: the user's own values replayed, bounded choices through Jev with calibrated probabilities, never submits, profile local. Nobody publishes coverage; you have 1,849 Greenhouse fills at 0 entry failures and 702 Ashby fills with measured medians, and publishing those with n is the moat. Caveat from a 400-application test: callbacks tracked the résumé, not autofill ([resumeoptimizerpro](https://resumeoptimizerpro.com/blog/autofill-job-applications-chrome-extension)), which is the thesis anyway. Greenhouse now fingerprints fake and duplicate applicants via Real Talent + CLEAR ([June 2025](https://www.greenhouse.com/newsroom/greenhouse-and-clear-announce-partnership-to-enable-candidate-verification)); a tool that never applies on someone's behalf is on the right side of that.

## 4. Trust and safety constraints for shipping

- **Chrome Web Store.** Privacy policy required even for data "processed or stored locally"; prominent in-product disclosure and affirmative consent; encrypted storage and transport; from 1 Aug 2026 data must be "strictly necessary to the disclosed single purpose" and post-install handling changes disclosed ([user-data FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq), [2026 update](https://developer.chrome.com/blog/cws-policy-updates-2026)). *Implies:* local-first is a feature, not an exemption; enabling the learning loop is a disclosable change.
- **Greenhouse.** Legal hub lists the MSA (customers), privacy policy, CCPA candidate notice, bias-audit statement; I found no candidate-facing term forbidding assisted filling; `boards.greenhouse.io/robots.txt` disallows only `/embed/`; Greenhouse ships its own autofill ([legal hub](https://www.greenhouse.com/legal), [robots](https://boards.greenhouse.io/robots.txt)). *Implies:* assisted filling in the user's own tab is not prohibited by anything found; dedupe and never submit.
- **Ashby.** Customer ToS has no automation clause and binds customers, not candidates; `jobs.ashbyhq.com/robots.txt` disallows `/meeting/`, `/b/`, `/api/` ([terms](https://www.ashbyhq.com/resources/terms), [robots](https://jobs.ashbyhq.com/robots.txt)). *Implies:* robots.txt addresses crawlers, but FirstPlay reads `ApiJobPosting` under `/api/`; do it only for the posting the user opened, never as a crawl, and say so.
- **Workday.** Applicant certifies everything is "true, accurate and complete"; falsification is grounds for termination; recruitment sites run bot-mitigation cookies ([terms](https://www.workday.com/en-ca/company/careers/terms-conditions.html), [cookie notice](https://www.workday.com/en-us/privacy/recruitment-cookie-notice.html)). *Implies:* liability sits with the user, so every value must be theirs and visible before submit; don't evade bot checks.
- **LinkedIn** bans extensions that "scrape, modify the appearance of, or automate activity" ([policy](https://www.linkedin.com/help/lms/answer/a1341387)). *Implies:* stay off LinkedIn.
- **Self-identification.** EO 11246 revoked 21 Jan 2025 (EO 14173) and its regulations rescinded ([Federal Register](https://www.federalregister.gov/documents/2025/07/01/2025-12276/rescission-of-executive-order-11246-implementing-regulations)); the Section 503 rule effective 21 Sep 2026 retired Form CC-305 and the disability invitation on ADA-conflict grounds, while race/sex (Title VII, EEO-1) and veteran self-ID persist where applicable ([Crelate summary](https://www.crelate.com/blog/disability-self-identification-form-application)). *Implies:* self-ID sections will churn for a year; separate opt-in, default decline/blank, never generalised, never transmitted.
- **Mobley v. Workday.** Conditional collective certified May 2025; June 2026 order lets race, sex, age and disability claims proceed; the vendor can be the employer's "agent" ([CDF](https://www.cdflaborlaw.com/blog/federal-court-grants-preliminary-certification-in-landmark-ai-hiring-bias-case)). *Implies:* demographic answers are litigation-sensitive; local-only storage is a selling point, and FirstPlay must never *decide* one.

## 5. Recommendation

**(i) Minimal v1 loop the evidence supports.** Capture: per-field diff of filled vs user-final value, keyed by ATS + form/field signature + normalised question text + option set. Replay: exact-key hits fill with a "from your answer on <org>, <date>" tag. Propose: when a value recurs on >= 2 distinct orgs, show a one-line diff ("Add to profile: willing to relocate = No?") with provenance; never auto-promote. Accept: write a typed fact with timestamp and decay, and hand Jev a labelled example. Nothing is generated; only what the user typed is replayed.

**(ii) Metrics to publish, each with n.** Replay rate = fields filled from memory / fields the user had answered before. Questions-asked-twice per user per 30 days (headline number; goal trends to zero). Coverage = fields filled / fillable, per ATS, from the live runs. Precision audit = sampled fills vs user-final values, published quarterly. Self-ID touched = 0 unless opted in.

**(iii) Three things not to build yet.**
1. Model-written answers or essays: the applicant certification makes them the user's legal statement, and "invents skills/expertise" is a top complaint for Jobright and Massive.
2. Auto-submit or a background agent: every sub-3-star product in the table does it, LinkedIn bans it, Greenhouse now fingerprints it, and Sonara's duplicate-application failures show the downside.
3. A self-modifying skill library (Voyager/AWM online induction): CoALA calls procedural writes risky, the budget-matched 2026 study shows the gains evaporate at equal cost, and hand-written procedures already run at 0 entry failures.
